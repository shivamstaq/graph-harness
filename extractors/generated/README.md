# `extractors/generated/` — generated-artifact extractors (P2.T28-T30)

Two extractors live here. Both emit `code.framework.GeneratedArtifact`
entities anchored to `code.core` via a `path_glob` selector. They run
on every `code.core.FileChanged` event.

| Extractor           | Confidence | Trigger                                                                 |
|---------------------|-----------:|-------------------------------------------------------------------------|
| `generated.heuristics` | 0.99 | header sentinel **AND** filename pattern both match                     |
| `generated.heuristics` | 0.85 | header sentinel matches; filename does not                              |
| `generated.heuristics` |   —  | filename pattern matches; sentinel absent → `UnverifiedGeneratedArtifact` |
| `generated.manifest`   | 1.00 | path matches a workspace-declared glob in `extractors.toml`             |

## Sentinel allowlist (`generated.heuristics`)

Detection scans the first 8 lines (`common.MaxSentinelLines`) of the
changed file against a **closed** allowlist (extending it requires a
PR). Patterns, in priority order (most-specific first):

| Generator label       | Regex                                                                  | Typical source                       |
|-----------------------|------------------------------------------------------------------------|--------------------------------------|
| `protoc-gen-go-grpc`  | `^// Code generated by protoc-gen-go-grpc.* DO NOT EDIT\.`             | gRPC stubs (`*_grpc.pb.go`)          |
| `protoc-gen-go`       | `^// Code generated by protoc-gen-go[. ].* DO NOT EDIT\.`              | protobuf messages (`*.pb.go`)        |
| `stringer`            | `^// Code generated by "stringer[^"]*".* DO NOT EDIT\.`                | `go generate` + `stringer`           |
| `go-generate`         | `^// Code generated by .* DO NOT EDIT\.`                               | generic Go-gen convention            |
| `openapi-generator`   | `^// Generated by openapi-generator`                                   | openapi-generator-cli output         |
| `ts-codegen`          | `^// This file is auto-generated by .* DO NOT EDIT`                    | graphql-codegen, swagger-codegen, …  |
| `python-autogen`      | `^# AUTOGENERATED`                                                     | python codegen banner                |
| `python-generated-by` | `^# Generated by `                                                     | python codegen banner (alt)          |
| `do-not-edit-hash`    | `^# DO NOT EDIT\. Generated by`                                        | terraform-docs, etc.                 |

## Filename allowlist (`generated.heuristics`)

Used as a corroborating signal (raises confidence when a sentinel
also matched) or as the trigger for the **escape-hatch**
`UnverifiedGeneratedArtifact` event (filename matched but no sentinel
— user confirms).

| Glob                | Suspected generator |
|---------------------|---------------------|
| `*_pb.go`, `*.pb.go` | `protoc`           |
| `*_pb.ts`, `*.pb.ts` | `protoc`           |
| `*_pb.py`, `*_pb2.py`, `*_pb2_grpc.py` | `protoc` |
| `*.pb.gw.go`        | `grpc-gateway`      |
| `bindings.gen.go`   | `abigen`            |
| `*.gen.go`          | `go-generate`       |
| `*.generated.ts`    | `ts-codegen`        |
| `*_string.go`       | `stringer`          |
| `mock_*.go`, `*_mock.go` | `mockgen`       |

Matches are `path.Match`-style globs (Go stdlib `path` package). Both
the basename and (if the glob contains `/`) the full normalised
forward-slash path are tried.

## `UnverifiedGeneratedArtifact` escape hatch (plan §5 risk row)

Files whose **name** matches a generator-output pattern but whose
**header** lacks any DO NOT EDIT sentinel produce a workspace-level
`UnverifiedGeneratedArtifact` notice instead of a confident
`GeneratedArtifact`. The payload carries:

```json
{
  "path": "mock_foo.go",
  "suspected_generator": "mockgen",
  "reason": "filename matched known-generator pattern; no DO NOT EDIT sentinel found"
}
```

The user has three remediation paths:

1. **Confirm by sentinel** — add a `// Code generated by … DO NOT EDIT.` banner.
2. **Confirm by manifest** — add the path/glob to `generated_patterns` in `.graph-harness/extractors.toml` (the `generated.manifest` extractor will start emitting `GeneratedArtifact` for it at confidence 1.0).
3. **Disregard** — leave the file as-is; the notice repeats on subsequent edits but never blocks the pipeline.

The notice is also useful as a real-world signal that the closed
allowlist is becoming insufficient and a new sentinel pattern (or
filename glob) might warrant a PR.

## Manifest patterns (`generated.manifest`)

Workspace `.graph-harness/extractors.toml`:

```toml
generated_patterns = [
  "*.gen.zig",                  # custom generator not in the closed allowlist
  "vendor/embedded/*.go",       # vendored generated source
  "schemas/*.generated.json",
  "i18n_translations.py",       # exact filename
]
```

The extractor reads the patterns once at construction; restart the
daemon to pick up changes (Pass 0's lifecycle model — runtime
reload lands later).

Globs use `path.Match` semantics: `*` matches a single path component;
no doublestar / recursive form in v1.

## Event shapes

`GeneratedArtifactAdded` payload (canonical):

```json
{
  "id": "GeneratedArtifact:<sha-prefix>",
  "kind": "GeneratedArtifact",
  "path": "foo.pb.go",
  "generator": "protoc-gen-go",
  "sentinel": "// Code generated by protoc-gen-go. DO NOT EDIT.",
  "anchored_to": {
    "anchors": [{"kind": "path_glob", "value": "foo.pb.go"}],
    "unique": true
  },
  "provenance": {
    "confidence": 0.99,
    "freshness": "current",
    "source_class": ["extractor:framework"],
    "produced_by": "extractor:framework:generated.heuristics"
  }
}
```

For `generated.manifest` emissions, `generator` is `"manifest"` and
`sentinel` carries the matching glob prefixed with `manifest:` (e.g.
`"sentinel": "manifest:*.gen.zig"`) so downstream consumers can see
which user-declared pattern fired the event.

## Why two extractors and not one

The two run side-by-side and emit independently. A workspace can
disable one without losing the other:

- `generated.heuristics` is the "we know these patterns" detector —
  good for green-field repos but blind to user-private generators.
- `generated.manifest` is the user-declared override — good for
  workspaces with bespoke codegen pipelines or for silencing the
  Unverified-notice for known-good files.

Both extractors are enabled by default; disable via
`graph-harness extractors disable generated.heuristics` or by adding
the name to `[disabled]` in `extractors.toml`.

## Testing

Each extractor ships fixtures under `testdata/`:

- `extractors/generated/heuristics/testdata/` — one file per sentinel
  pattern, one per filename pattern, one per escape-hatch case, and a
  hand-written control.
- `extractors/generated/manifest/testdata/extractors.toml` — sample
  workspace manifest exercised by the real-config integration test.

Run:

```bash
go test ./extractors/generated/...
go vet  ./extractors/generated/...
```
